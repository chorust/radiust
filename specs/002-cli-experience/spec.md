## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一条命令预览原始雷达图片 (Priority: P1)

用户希望在来源尚无经过验证的科学解码能力时，直接预览原始图片，判断资料是否正确获取。

**Why this priority**: 当前这类来源需要先下载再查看，直接预览可消除最明显的使用障碍。

**Independent Test**: 用离线 PNG/GIF 样本，分别运行来源 raw 预览与本地文件预览，确认可显示图片且没有科学输出产生。

**Acceptance Scenarios**:

1. **Given** 来源有合法图片但没有科学解码器，**When** 执行 `radiust cat SOURCE --station STATION` 或 `radiust cat SOURCE --raw --station STATION`，**Then** 默认展示该站最新原始像素图片，标明 raw、来源和已知观测时间，不因科学解码能力缺失而失败。
2. **Given** 查询仍匹配多个站点、产品或帧，**When** 请求 raw 预览，**Then** 报告候选身份与所需选择参数，不任意选择第一项；`--at` 仅在结果确实唯一时足以消除歧义。
3. **Given** stdout 被重定向，**When** 使用 `--renderer text`，**Then** 输出可读的图片摘要且无图片控制序列；使用其他 renderer 时在获取资料前报错并提示文字模式。
4. **Given** 已保存的原始 PNG/GIF，**When** 用 `cat --file PATH --renderer text` 离线查看，**Then** 成功显示尺寸、文件身份及已知信息，未知时间和单位保持未知。
5. **Given** 获取或显示中取消、失败或图片损坏，**When** 命令结束，**Then** 清理本次临时资料并恢复终端，不删除已有 raw、缓存中的其他资料或正式成果。

### User Story 2 - 省略时间参数即可取得最新资料 (Priority: P1)

用户希望日常查询、下载和来源预览默认使用最新资料，同时保持显式时间查询可预测。

**Why this priority**: 减少重复输入并统一相关命令的默认行为。

**Independent Test**: 对固定多站点样本比较省略选择器与显式 `--latest` 的结果，再检查指定时间、范围和冲突参数。

**Acceptance Scenarios**:

1. **Given** 未提供时间选择器，**When** 运行 `discover SOURCE`、`download SOURCE` 或来源模式 `cat SOURCE`，**Then** 与显式 `--latest` 的查询结果一致。
2. **Given** 显式提供 `--at` 或完整 `--start/--end`，**When** 运行支持该选择器的命令，**Then** 使用指定时间，不附加隐式 latest；显式 `--latest` 与其他选择器并用仍报参数错误。
3. **Given** 多个站点各有最新帧，**When** discover 或 download 未限定站点，**Then** 保留当前产品选择规则并返回所有所选站点的最新帧及逐帧报告；cat 仍要求唯一帧。
4. **Given** 无资料、全部过期、范围不完整或时间无效，**When** 发起查询，**Then** 明确区分无数据与参数错误，不静默替换用户时间。
5. **Given** 本地文件含多个时刻，**When** 未指定时刻，**Then** 仍要求明确选择；来源查询的默认 latest 不改变文件预览规则。

### User Story 3 - 一次查看全部来源最新状态 (Priority: P2)

用户希望一次查询获得所有来源的最新资料及不可用原因，用于值班检查和自动化巡检。

**Why this priority**: 消除逐来源执行命令的重复劳动，同时保留失败来源的可见性。

**Independent Test**: 使用包含成功、无数据、缺凭据、退役、网络受限、失败和超时的离线目录，核对每个目标均有结果且统计一致。

**Acceptance Scenarios**:

1. **Given** 完整来源目录，**When** 执行 `radiust discover all --latest --json` 或省略 `--latest`，**Then** 遍历目录中有效的来源、产品、站点组合，每个查询目标均有结果，来源不会因无站点或前置失败而消失。
2. **Given** 部分来源不可查询，**When** 批量任务运行，**Then** 其他来源继续完成，不可用项保留安全原因；成功发现但不能科学解码的帧仍可见并标注解码限制。
3. **Given** 网络未获允许或缺少凭据，**When** 查询全部来源，**Then** 不擅自联网或读取旧仓库凭据，并为受限目标给出状态。
4. **Given** 某来源持续阻塞，**When** 达到统一任务时间预算，**Then** 返回已完成结果和剩余目标的超时或未开始状态，任务不会无限等待。
5. **Given** 批量任务被取消，**When** 输出最终报告，**Then** 已完成结果保留，其余目标标记取消或未开始，报告标明中断并返回 130。

### User Story 4 - 快速看懂终端输出 (Priority: P1)

用户希望命令结束后能快速识别来源、时间、结果和下一步操作，运行过程中能知道任务是否仍在推进。

**Why this priority**: 展示优化是本次明确目标，覆盖日常命令的共同使用体验。

**Independent Test**: 在 40、80、120 列终端、禁用颜色及输出重定向环境中查看固定结果；核对信息完整性及机器输出兼容性。

**Acceptance Scenarios**:

1. **Given** list、discover、download 有多项结果，**When** 查看默认输出，**Then** 显示有标签的表格或逐条记录及汇总，而非对象内部表示；失败项能定位来源、原因和适用的下一步建议。
2. **Given** doctor、config、cache 返回结果，**When** 查看默认输出，**Then** 使用有标签的分组或键值展示，配置敏感值脱敏。
3. **Given** 40 列终端、长标识或中文描述，**When** 展示结果，**Then** 自动换行或改为逐条布局，身份、状态、时间和错误原因不被截断丢失；80/120 列显示紧凑且无重叠。
4. **Given** 长时间查询或下载，**When** 在交互终端运行，**Then** stderr 显示当前阶段和已完成/总目标数；总数未知时不显示虚假百分比，结束或取消后清除进度行并恢复光标。
5. **Given** `--json`、非交互环境、禁用颜色或 quiet 模式，**When** 输出结果，**Then** JSON 保持单一完整报告，纯文本不含终端控制序列，状态无需颜色也可区分；quiet 不屏蔽显式 JSON 和错误。

### User Story 5 - 复现全部旧来源的灰度显示 (Priority: P1)

用户希望在新 CLI 中继续使用旧项目的来源专属灰度显示，维护者希望逐来源确认显示一致性，并明确区分显示迁移和科学验证。

**Why this priority**: 用户已明确将全部 TODO 纳入本次；灰度显示迁移也是 cat raw 显示路径完整交付的一部分。

**Independent Test**: 对每个具备合法 raw 与对应配置的来源/产品路径，使用相同离线输入比较新旧灰度结果及溯源记录；缺少材料的路径检查 blocked 记录。

**Acceptance Scenarios**:

1. **Given** 来源具有匹配的已验证显示配置，**When** 使用 `cat SOURCE --legacy-display` 查看唯一帧，**Then** 使用其 legacy 灰度显示路径，标明转换版本与仅用于显示，保持原始资料不变且不生成正式科学输出；默认或 `--raw` 模式始终显示原始像素，不自动套用转换。
2. **Given** 来源专属颜色表、阈值、背景与范围掩码、裁剪及尺寸规则，**When** 对同一合法样本执行新旧转换，**Then** 输出尺寸、逐像素灰度、透明区域、背景和缺测语义一致；有意修正的历史差异单独记录，不作为无差异通过。
3. **Given** 明确确认由旧 post_process 生成的灰度资料，**When** 解释其编码，**Then** 遵守既有灰度对应关系，透明像素保持缺测、不透明黑色可代表零值；普通 RGB/WMS 图片或来历不明的灰度图不得仅凭亮度套用反算。
4. **Given** AU、CA、ES、ID、KR、MY、NZ、PH、SG、TH、TW、VN、FR、PT 和 RainViewer/Windy/BMKG 瓦片路径清单，**When** 审阅迁移结果，**Then** 每个纳入范围的旧来源及产品路径都有通过、差异待复核或 blocked 的明确状态；缺合法 raw 或配置者不被宣称完成。OpenSnow/WU 保留在采集清单，但按用户决定不纳入本次 legacy-display 范围。
5. **Given** 瓦片路径具备完整合法输入与经过验证的显示组合规则，**When** 回放唯一帧，**Then** 按来源规则得到可比对的灰度显示；缺瓦片或规则不明时报告 blocked，不任意拼接或填零。
6. **Given** 完成一次来源显示验证，**When** 检查迁移记录与交接文档，**Then** 能定位算法版本、输入与输出指纹、裁剪区域、对比结果和已知差异；显示通过不改变原有科学验证状态。

### Edge Cases

- 最新地址内容在发现后更新：不能把另一时刻图片当作已选帧；无法确认时明确失败。
- 单帧由多个 artifact 或瓦片组成：仅在具备完整输入和已验证的来源专属显示组合规则时进入 legacy 显示路径；其他情况明确报告限制并提示下载全部资料，不任意选择单文件。
- GIF 含多个动画画面：本次静态预览使用第一画面并标明该选择，不把动画内部时间推断为观测时间。
- 非图片 raw、损坏图片、超大图片：提供安全的格式或资源限制错误，不尝试科学解码兜底。
- 透明区域、黑色像素和 RGB/WMS 图片：依据已验证来源规则区分背景、缺测和零值；只有明确的 legacy 编码来源证据才允许反算，不能按亮度猜测。
- 颜色表版本、产品配置、裁剪边界或尺寸规则不匹配：不借用其他来源配置；转换状态标记 blocked，保留可直接预览的原图。
- 修补缺口和缩放可能改变像素：必须作为版本化显示规则接受对比，不能据此补造科学观测值。
- 无站点产品或发现前失败：结果允许未知身份字段为空，仍保留已知来源和失败状态。
- 不同来源的产品、站点同名：使用完整来源/产品/站点身份区分，统计不能重复计数。
- 上游错误或描述包含控制字符、令牌、带凭据 URL：安全展示，既不能触发终端控制也不能泄密。

## Requirements *(mandatory)*

### Functional Requirements

命令名、选项与报告字段属于用户可见契约；内部实现和技术选型由后续计划决定。

- **FR-001**: 来源模式 cat 默认以原始像素预览唯一帧的 PNG/GIF raw，`--raw` 显式选择相同模式；只有 `--legacy-display` 可应用匹配且验证通过的旧灰度显示转换，`--decoded` 才执行科学解码。原图预览不执行重网格或正式输出提交。（US1）
- **FR-002**: raw 模式必须保留唯一帧选择要求；时间、产品或站点歧义必须列出候选及修正建议，不任意选取。多 artifact 仅允许 FR-019–024 定义的已验证显示组合路径，其他情况及不支持的 raw 格式必须明确报错。（US1）
- **FR-003**: raw 预览必须支持 text、ansi、kitty、iterm2 与 auto 的现有能力规则；未知终端中 auto 有界降级，显式不兼容 renderer 明确失败。非 TTY 仅允许显式 text，获取前完成检查。（US1）
- **FR-004**: 本地 PNG/GIF 必须可离线回放；图片摘要展示身份、尺寸、raw 标记和已知时间，未知值明确标识。GIF 静态首画面必须标注；`--raw` 与 `--file` 同用报参数错误，文件模式本身即可预览。（US1）
- **FR-005**: raw 预览必须拒绝变量、物理范围和科学配色选项；图像缩放仅改变显示。取消、失败及成功均释放临时资源，不触碰正式输出，取消退出码为 130。（US1）
- **FR-006**: discover、download、来源模式 cat 在未提供 latest、at、start/end 时必须默认 latest。显式时间选择阻止注入默认值，显式互斥选择器仍报错；拼写仅支持 `--latest`。（US2）
- **FR-007**: 默认 latest 必须按所选产品和站点分别取最新帧；discover/download 允许多帧并报告全部，cat 要求唯一帧。现有产品默认值、起报时间、时效和文件模式规则必须保留。（US2）
- **FR-008**: `discover all` 必须覆盖目录中全部有效产品/站点组合；没有站点的产品作为单独目标。某来源无法展开时至少保留一条来源级原因记录。（US3）
- **FR-009**: 本次 `discover all` 仅支持默认或显式 latest；at、start/end、base-time、product、station 参数必须在查询前拒绝并提示使用单来源查询；允许沿用 max-age 时效限制。（US3）
- **FR-010**: 批量发现必须区分成功、无数据、过期、缺凭据、退役、网络受限、上游失败、超时、取消及未开始；发现成功但无科学解码能力时保留帧及独立的能力限制说明，不伪装为无数据。同一目标若存在无法唯一选择的同时间候选，返回歧义状态与安全原因，不任意挑选；该状态计入非成功结果。（US3）
- **FR-011**: 批量发现结果必须稳定排序，包含 `source/product/station/status/valid_time/error` 字段，未知值为空；error 包含安全原因与可重试性。沿用 `schema_version: 1` 报告外层、单一最终报告及 counts，额外能力说明不得覆盖发现状态。（US3）
- **FR-012**: counts 必须包含总目标数及每种结果状态的数量，状态数之和等于目标数；排序按来源、产品、站点、有效时间，未知值排在已知值之前。全部目标成功返回 0；有成功且有非成功返回 4；无成功且只有无数据/过期返回 3；其余无成功返回 5；参数错误返回 2；中断优先返回 130。（US3）
- **FR-013**: 全量查询必须服从既有网络许可、凭据、来源限额、重定向和资源上限；并发不得超过配置上限。整批共享一个可配置时间预算，默认 300 秒，预算耗尽后 5 秒内结束并报告已完成、超时和未开始目标，不对每个来源重新计时。（US3）
- **FR-014**: list/discover/download 默认报告必须有标题、适用的身份/状态/UTC 时间或输出位置，以及汇总；doctor/config/cache 使用带标签的分组信息。失败项包含错误原因及有依据的下一步建议；无数据应有明确文字，不输出空白成功报告。（US4）
- **FR-015**: 文本展示必须适配 40/80/120 列，长字段可换行但关键身份与原因不得丢失；状态必须有文字，遵守 `NO_COLOR`，非 TTY 不发送颜色、光标或图片控制序列。（US4）
- **FR-016**: 交互任务必须在 stderr 提供阶段与完成数进度；非 TTY 不输出动态刷新。quiet 关闭人类报告与进度但保留错误和显式 JSON；verbose 增加安全诊断，与 quiet 互斥。进度不得覆盖图片或污染 stdout 的最终报告。（US4）
- **FR-017**: 既有 JSON 字段、退出码及单来源显式查询含义必须兼容；所有人类/机器报告与诊断均需凭据脱敏，对不可信文本中的终端控制字符做安全展示。（US1–US5）
- **FR-018**: 用户文档必须说明默认 latest、多站点规则、默认 raw 与显式科学预览边界、all 的结果与退出码、终端降级和管道用法，并提供可离线复现的示例；`docs/cli.md` 必须说明仅由 `--legacy-display` 启用 legacy 显示、原图像素保持、版本提示与科学验证边界。（US1–US5）

- **FR-019**: 必须迁移 AU、CA、ES、ID、KR、MY、NZ、PH、SG、TH、TW、VN、FR、PT 及 RainViewer/Windy/BMKG 的全部旧灰度显示产品路径，建立逐路径覆盖清单；每条纳入路径必须有通过、差异待复核或 blocked 状态，blocked 必须列出缺少的合法 raw、配置或其他必要证据。OpenSnow/WU 不属于本次 legacy-display 覆盖范围，仍保留独立的采集迁移记录。（US5）
- **FR-020**: 显示规则必须按来源和产品版本化，保留旧基础配置与产品覆盖规则中的裁剪区域、颜色表、零值颜色表、颜色处理步骤、有效值和零值阈值、背景/范围掩码、圆盘范围、缺口修补及缩放语义。每项规则均须有旧行为依据与离线对比，不可静默省略。（US5）
- **FR-021**: legacy 显示结果必须遵守既有 `0..224` 灰度编码约定：`gray = clip(dBZ * 16 / 5, 0, 224)`；仅当资料确由该 post_process 编码产生且来源可证实时，才允许按 `dBZ = gray / 16 * 5` 解释。既有版本标识 `旧项目-gray-dbz-v1` 必须可追溯；未知 RGB/WMS 不能按亮度反算。透明像素保留缺测质量，不透明黑色可以表示零值，原始资料不得被改写。（US5）
- **FR-022**: 只有 `cat --legacy-display` 对有匹配且验证通过的显示规则的资料应用 legacy 转换，标题及 text 摘要标明显示模式、规则版本和非科学验证结论；无匹配规则时直接显示原图并标明转换不可用原因。匹配规则执行失败必须明确失败，不能悄悄回退并宣称迁移通过。默认或 `--raw` 模式始终保留原始像素；普通本地文件无来源证据时保持原图；迁移验证须支持带来源/产品与规则身份的离线回放。（US1、US5）
- **FR-023**: 瓦片显示必须保留经验证的来源组合、颜色解释和范围规则，仅对唯一帧且完整合法输入执行；缺瓦片、组合规则或身份无法确认时保持 blocked，不任意拼接、补零或重网格。FR/PT 专属颜色映射与各瓦片路径均须独立比对，不因其他来源通过而视作通过。（US5）
- **FR-024**: 每条具备合法样本与配置的路径至少完成一组新旧离线对比，核对尺寸、逐像素值、透明/背景与缺测；无有意变更时要求完全一致，有意差异须逐项记录原因、影响和复核结论，待复核不得标为通过。记录来源、产品、灰度算法版本、输入 raw hash、输出 hash、裁剪区域、基准身份及已知差异，并更新 `migration/sources/*.json`、`validation-results/us2.md` 和 `validation-results/us6-inventory.md`；不得读取旧仓库凭据或将显示验证升级为科学验收。（US5）

### Key Entities

- **查询目标**: 来源、产品及可选站点组成的有效查询单元，用于完整覆盖与计数。
- **帧身份**: 来源、产品、站点、有效时间和适用的起报时间，用于唯一选择和消除歧义。
- **原始预览资料**: 未经科学解释的图片及已知出处、尺寸、内容身份；显示成功不代表科学验证通过。
- **发现结果**: 查询目标的状态、可选帧信息、安全错误和解码能力限制。
- **最终报告**: 本次任务的查询条件、有序结果、状态统计及中断标记，同时供人类和自动化使用。

- **灰度显示规则**: 来源/产品对应的版本化颜色、范围、裁剪和尺寸规则，决定 raw 如何显示而非科学有效性。
- **显示迁移证据**: 路径覆盖状态、输入/输出内容指纹、规则版本、对比基准、差异与阻塞原因，可独立复核。
