# Feature Specification: Rust 核心迁移与性能优化

**Feature Branch**: `main`（当前分支；未配置分支创建 hook）

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "Rust 迁移与性能优化方案 migration.md"；范围以仓库根目录 `migration.md` 为准。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 独立运行完整命令行工具 (Priority: P1)

用户在 macOS arm64 上安装命令行程序，即可查询来源、发现资料、下载成果、预览、诊断及管理配置和缓存，无需为日常命令安装 Python。

**Why this priority**: 独立入口和统一业务能力是未来桌面版复用与本轮性能改进的基础。

**Independent Test**: 在无 Python 的干净 macOS arm64 环境，用离线样本逐一运行 `list`、`discover`、`download`、`cat`、`doctor`、`config`、`cache`，核对结果、退出状态和产物。

**Acceptance Scenarios**:

1. **Given** 原生程序已安装且没有 Python，**When** 运行现有命令及主要选项，**Then** 每个命令均可完成相应任务，机器报告和退出状态保留既有含义。
2. **Given** 任一已登记内置来源，**When** 查询目录并以合法离线资料执行适用的操作，**Then** 来源身份、能力及限制均可查询；退役来源仍显示状态且不发起请求。
3. **Given** 合法资料与指定格式，**When** 下载并读回成果，**Then** 适用的 NetCDF4、GeoTIFF、PNG、Zarr v2 输出可独立生成和读取，同身份的既有正式成果可校验、可复用。
4. **Given** 来源仅有原图或显示规则，尚无科学解码证据，**When** 预览或请求科学输出，**Then** 可进行适用的原图/显示预览，但不得把图片可获取等同于科学有效。

---

### User Story 2 - 一次快速发现多个来源 (Priority: P1)

值班用户一次选择全部或多个来源，在合理时间内看到每个查询目标的最新状态；慢来源或失败来源不拖住其他来源。

**Why this priority**: 当前全量发现逐目标等待，直接影响日常巡检。

**Independent Test**: 使用含快、慢、失败和阻塞来源的固定离线回放，分别执行 `discover all` 与 `discover au vn`，检查耗时、状态、顺序和并发上限。

**Acceptance Scenarios**:

1. **Given** 多个可查询来源，**When** 执行 `discover all` 或 `discover au vn`，**Then** 多个独立目标可同时推进，报告包含全部目标的有序结果、状态计数及逐目标原因。
2. **Given** 某目标失败、无数据或需要凭据，**When** 其他目标仍可查询，**Then** 其他目标继续完成，失败目标保留明确且脱敏的状态，计数与结果一致。
3. **Given** 整批时间预算用尽或用户中断，**When** 命令结束，**Then** 已完成结果保留，未完成目标标明超时、取消或未开始；中断返回 130。
4. **Given** 重复来源、`all` 与其他来源混用，或多来源模式使用单来源专用选择条件，**When** 解析请求，**Then** 在请求数据前报告参数错误；单来源原有选择条件仍可用。

---

### User Story 3 - 高效且安全地批量下载 (Priority: P1)

用户下载多个帧时更快得到结果，且中断或单帧失败不会损坏已提交成果。

**Why this priority**: 下载是主要耗时流程，也是正式数据的完整性边界。

**Independent Test**: 用多帧离线资料和可控输出位置，覆盖完成、部分失败、中断、同路径冲突和旧成果复用。

**Acceptance Scenarios**:

1. **Given** 多个独立帧且设置并发上限，**When** 批量下载，**Then** 多帧可同时推进，实际活动任务不超过上限，报告按输入顺序列出结果。
2. **Given** 一个帧失败且选择继续，**When** 任务结束，**Then** 其他帧可完成，失败帧有明确原因，总体报告标明部分失败。
3. **Given** 一个帧失败且选择停止，或用户中断，**When** 任务停止，**Then** 不再开始新帧，已完成成果保留，未完成临时资料清理，正式成果不出现半提交状态。
4. **Given** 已有可验证的旧格式成果，**When** 再次下载同一身份，**Then** 可按现有规则跳过或复用；无法验证或处理语义已变化的成果不得被错误视为新结果。

---

### User Story 4 - Python 科学工作流按需转换 (Priority: P2)

研究用户继续从 Python 调用查询和处理能力，在需要时把结果转换为 xarray 对象或使用 Python 侧 Zarr 适配。

**Why this priority**: 保留科学分析体验，同时让日常命令和基础调用不依赖 Python 科学栈。

**Independent Test**: 在仅安装基础 Python 包及安装可选科学依赖的两种环境调用同一查询，检查基础返回值、显式转换和迁移文档。

**Acceptance Scenarios**:

1. **Given** 仅安装基础 Python 包，**When** 调用发现、获取或下载，**Then** 返回可查询身份、数值/质量信息及状态的绑定对象，不要求安装 xarray。
2. **Given** 已安装科学可选依赖，**When** 对获取结果显式调用 `to_xarray()`，**Then** 数值、质量位、坐标和时间与原结果一致；Python 侧 Zarr 适配仍可用。
3. **Given** 旧默认 xarray 返回值或 Python 来源插件接口用户，**When** 查阅迁移说明，**Then** 能找到新调用方式、受影响行为及自定义来源的替代接入边界。

---

### User Story 5 - 从已有资料快速预览首帧 (Priority: P2)

用户查看原图或本地成果时，迅速看到所选帧，不因无关帧或不需要的科学处理而等待。

**Why this priority**: 交互等待时间是本轮明确的性能重点。

**Independent Test**: 用相同的代表性原图和多帧本地文件，比较迁移前后的首帧可见时间，并核对帧身份和显示模式。

**Acceptance Scenarios**:

1. **Given** 唯一原始图片，**When** 执行 `cat`，**Then** 首帧按既有 raw/legacy 显示规则出现，不产生不需要的科学输出。
2. **Given** 多帧本地资料，**When** 明确选择一帧预览，**Then** 展示该帧及其身份；选择不唯一时继续报告歧义。

### Edge Cases

- 缺少系统浏览器或 OCR 程序、凭据不足、网络未获允许：相关来源给出可操作的限制说明；无关来源和命令仍可运行，不隐式安装外部程序。
- 多来源发现共享上游或同一主机、重定向到另一主机：请求仍遵守统一的网络许可、访问限制和资源上限；重复资料不会成为重复帧。
- 最新地址在发现与获取之间改变、资料损坏或超限：不得把不匹配内容提交为所选帧；报告可追溯错误。
- 旧缓存与新程序共用目录：合法旧条目可识别，损坏条目可隔离；清理缓存不删除正式成果。
- 并发任务写入同一位置、远端提交中断：最终成果只在完整且可验证时可见，已有成果不被半成品覆盖。
- 数据值、质量位、缺测、透明、坐标或时间未知：保留未知/无效语义，不用图像外观推断科学数值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 原生 macOS arm64 命令行程序 MUST 在无 Python 环境运行 `list`、`discover`、`download`、`cat`、`doctor`、`config`、`cache` 的现有主要功能，并保留适用的命令选项、机器报告和退出状态含义。（US1）
- **FR-002**: 系统 MUST 覆盖当前目录中的全部 24 个内置来源及其产品/站点目录、资料身份、可用状态和已验收能力；退役来源 MUST 可见但不得发起获取。（US1）
- **FR-003**: 系统 MUST 在原生命令行路径完成适用的资料获取、科学处理、预览、缓存管理、正式成果提交，以及 NetCDF4、GeoTIFF、PNG、Zarr v2 输出与本地成果预览，无需 Python 参与。（US1、US5）
- **FR-004**: 系统 MUST 保留原图/legacy 显示与科学验证的区别；未验收科学解码的来源不得仅凭图像获取成功而产生正式科学成果。（US1、US5）
- **FR-005**: `discover all` 和 `discover SOURCE...` MUST 同时推进多个独立目标，服从可配置的发现任务上限、共享网络限制及整批时间预算；报告 MUST 包含每个目标且顺序稳定。（US2）
- **FR-006**: 多来源发现 MUST 只接受 latest 与 max-age 选择；重复来源、`all` 与其他来源混用及单来源专用选择条件 MUST 在请求前报参数错误。单来源原有产品、站点和显式时间选择仍可用。（US2）
- **FR-007**: 多来源发现 MUST 保留既有逐目标状态、总数、脱敏错误及聚合退出状态；超时和中断 MUST 区分已完成、运行中和未开始目标，中断返回 130。（US2）
- **FR-008**: 批量下载 MUST 支持有界的同时处理，按输入顺序报告每帧结果；继续/停止策略、取消和同路径冲突 MUST 保留既有成果完整性。（US3）
- **FR-009**: 系统 MUST 识别并校验现有正式成果和缓存身份，按既有规则复用合法资料；处理语义变化时不得错误跳过需重做的成果，且不得将缓存视为正式输出。（US1、US3）
- **FR-010**: Python 基础包 MUST 提供发现、获取、下载及结果读取能力；`fetch` 默认返回绑定结果，xarray 转换 MUST 由显式 `to_xarray()` 完成，Python 侧 xarray/Zarr 适配作为可选能力提供。（US4）
- **FR-011**: 自定义来源接入 MUST 有文档化迁移路径；原有 Python 来源插件接口与默认 xarray 返回值的破坏性变化 MUST 明示并给出示例。（US4）
- **FR-012**: 系统 MUST 对网络许可、凭据保密、重定向、取消、超时和资源上限执行与现有契约等效的保护；诊断 MUST 区分核心能力与来源专用外部依赖。（US1–US3）
- **FR-013**: 系统 MUST 提供可被命令行及 Python 入口共同使用的独立核心能力，以支持后续桌面版接入；本次不交付桌面界面、后台服务或平台桥接。（US1）
- **FR-014**: 用户文档 MUST 覆盖原生命令安装、命令与输出兼容变化、Python 调用迁移、来源接入迁移、可选外部程序及各输出格式读回方式。（US1、US4）

### Key Entities

- **来源目录项**: 来源、产品、站点、活跃/退役状态及可用能力的登记信息。
- **查询目标**: 一次发现中的来源、产品、站点组合；每个目标恰有一个最终状态。
- **帧身份**: 来源、产品、站点、有效时间和适用的起报时间，用于发现、获取、缓存和成果复用。
- **数据场/数据集**: 数值、质量位、坐标、时间、单位及来源证据；与仅用于显示的像素区分。
- **任务报告**: 查询条件、按约定排序的逐目标/逐帧结果、状态计数、安全原因及中断标记。
- **正式成果与缓存条目**: 前者为可校验的对外结果，后者为可清理的复用资料；两者不可互相替代。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在无 Python 的干净 macOS arm64 环境，七组现有命令全部可用；24 个内置来源的目录覆盖率为 100%，与既有离线样本对应的帧身份和状态一致率为 100%。
- **SC-002**: 对已有合法验证样本，原图与 legacy 显示逐像素一致；已验收科学资料的数值、质量位、坐标和缺测语义一致；未验收来源错误生成科学成果的次数为零。
- **SC-003**: 在同一 macOS arm64 设备、相同输入与配置下，每个场景至少重复 30 次；离线 `list` 和 `discover all` 的第 95 百分位完成时间分别不超过现有版本的 50%。
- **SC-004**: 对四个独立延迟来源的固定回放，多来源发现第 95 百分位完成时间不超过现有逐来源流程的三分之二；每个目标都有且仅有一个最终状态，统计与逐项结果一致率为 100%。
- **SC-005**: 代表性 `cat` 场景中，首帧可见时间的第 95 百分位较现有版本降低至少 20%；预览内容和身份与所选帧一致率为 100%。
- **SC-006**: 相同验收场景下，整个任务的峰值内存不高于现有版本；并发峰值均不超过配置上限，完成、中断、超时后遗留临时文件或子进程数为零。
- **SC-007**: 旧正式成果可读回且校验通过；同身份合法成果的错误覆盖、错误跳过及半提交可见次数均为零。所有适用输出格式可由目标用户现有工具读回数据、时间和地理信息。
- **SC-008**: 原生程序与基础 Python 包均能在干净环境完成安装和离线主流程；可选科学依赖安装后，显式转换得到的数值、质量位、坐标和时间与原结果一致。迁移示例覆盖已知两类破坏性变化。

## Assumptions

- 本规格以仓库根目录 `migration.md` 为实施边界；它是代码归属和性能迁移计划，不改变 `docs/migration.md` 与 `migration/` 中既有的科学验收结论。
- 首次发布及正式性能验收限定 macOS arm64；其他平台不是本轮发布门槛。桌面 UI、后台服务、IPC 与 Swift 绑定留待后续。
- 原生 CLI 和未来桌面入口共享 Rust 核心；Python 只保留薄绑定及可选 xarray/Zarr 科学适配。Zarr v2 的原生命令行输出属于本次范围。这是用户明确提出的产品约束，具体模块与库的选择留到设计阶段。
- 浏览器来源可使用系统现有 Chromium，OCR 来源可使用系统现有 Tesseract；这些是来源专用的可选依赖，不随普通命令隐式安装。
- 原 Python 来源插件机制可破坏性迁移；新来源通过编译期扩展进入原生程序。Python `fetch` 默认返回类型也允许改变，但需迁移说明。
- 性能比较使用迁移前正式采集的基线，采用同机同样本至少 30 次测量；已有少量本机冒烟数据不作为基线。
- 离线回放和合法样本足以验收大部分行为；真实网络、凭据和来源限制继续遵守既有许可规则。
- `.specify/memory/constitution.md` 目前是未填写模板，未据此新增项目治理要求。
