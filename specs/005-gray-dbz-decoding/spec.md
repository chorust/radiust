# Feature Specification: 灰度编码 dBZ 解码与 gray/dbz 口径统一

**Feature Branch**: `main`（当前分支；特性标识为 `005-gray-dbz-decoding`）

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "我现在想完成一些科学解码的，可以认为 legacy 展示的灰度图（如果值域和旧项目一样的话 0～224，认为把灰度值 /16*5 就是 dBZ，这个是之前旧项目对齐过的），按这个先完成一版科学解码，同时想把项目现有 CLI/docs/代码里的 legacy 改成 gray 灰度口径，科学解码改成 dbz 口径。"

## Clarifications

### Session 2026-10-02

- Q: NZ 已验证 gray 基准在缩放后有 6 个可见像素超过224（最大229），如何兼容严格值域与15条来源路径？ → A: 仅在 dBZ 解码时截断到224，保留原 gray 图。该例外仅适用于已有通过规则生成的来源 gray；本地声明输入仍严格校验。结果须记录实际截断位置、数量和处理策略，已有无效掩码仍优先，不因截断变成有效像素。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从已确认的灰度编码读取 dBZ 值 (Priority: P1)

数据使用者已有按旧项目约定生成的灰度雷达图，希望读取可计算的反射率，而不止查看显示图。本版采用用户已确认的编码约定：有效灰度整数为 0～224，反算 `dBZ = gray / 16 * 5`，输出范围为 0～70 dBZ。用户能检查像素数值、缺测和编码来源；无需重新证明旧项目已确认的算术关系。

**Why this priority**: 将已经可用的灰度结果变为可计算数据，是本次科学解码的最小有用交付。

**Independent Test**: 对明确声明采用此编码的本地灰度样本解码，核对全部 225 个灰度值、透明像素及非法输入；不依赖公网、站点目录或地理定位。

**Acceptance Scenarios**:

1. **Given** 已确认编码的有效像素为 0、16、32、160、224，**When** 请求 dBZ 解码，**Then** 得到 0、5、10、50、70 dBZ，保留行列位置和图像尺寸。
2. **Given** 一张图含有效不透明黑色和完全透明像素，**When** 解码，**Then** 前者按编码得到 0 dBZ，后者保留为缺测，不把透明像素填成 0。
3. **Given** 没有可信来源关联的本地灰度文件，**When** 用户显式请求以约定灰度编码解读，**Then** 记录这项用户声明、核验像素条件并返回编码对应的 dBZ；普通打开文件不会自动作此声明。
4. **Given** 任一可见像素超过 224、不是整数灰度或三个颜色通道不相等，**When** 请求该编码解码，**Then** 给出可定位的输入错误，不静默裁剪、取亮度或转成成功数据。
5. **Given** 原图没有有效时刻或地理定位信息，**When** 解码和预览，**Then** 用户仍能读取像素空间 dBZ 值；结果明确缺少相应信息，不生成当前时间或推测经纬度。

---

### User Story 2 - 用 raw、gray、dbz 三种口径操作雷达资料 (Priority: P1)

CLI 和 SDK 使用者希望区分原始资料、灰度显示编码与 dBZ 反射率。用户在帮助、命令参数、报告和文档中使用一致术语；维护者在相关代码、资源和验证材料的活动命名中也使用这些术语。

**Why this priority**: 本次增加解码能力后，命名必须准确表达数据含义，避免将灰度显示和反射率混用。

**Independent Test**: 无网络检查帮助与文档示例，使用同一离线资料分别选择三种模式，核对输出模式、单位、错误和旧名称迁移行为。

**Acceptance Scenarios**:

1. **Given** 一条已有可用灰度转换的来源路径，**When** 用户以 `--gray` 预览，**Then** 得到与原灰度显示相同的像素，报告称为 gray 并标明编码和规则；灰度像素本身不标为 dBZ 数值。
2. **Given** 同一条路径，**When** 用户以 `--dbz` 预览，**Then** 得到编码对应的反射率值及标为 dBZ 的图例，报告可追溯到相同灰度转换。
3. **Given** 当前自动化仍使用 `--legacy-display` 或 `--decoded`，**When** 使用旧名称执行等价请求，**Then** 本版按兼容规则得到与对应新名称一致的结果，迁移提示不污染机器输出；新帮助和示例优先使用 gray/dbz。
4. **Given** 用户同时请求 raw、gray、dbz 中的不同模式，**When** 执行命令，**Then** 在获取资料前拒绝歧义；未指定模式的原图预览继续使用 raw。
5. **Given** 产品提供的是雨强或其他非反射率量，**When** 读取报告或科学文件，**Then** 仍保留真实物理量与单位，不因术语统一而改标为 dBZ。

---

### User Story 3 - 对已有灰度路径完成来源到 dBZ 的闭环 (Priority: P1)

数据使用者选择已有来源、产品、站点和时刻，系统从原始资料生成已验证灰度，再按约定得到 dBZ，供 CLI 和同步/异步 SDK 读取或保存。已有直接数值反射率产品继续使用其已验证规则。

**Why this priority**: 将通用解码接到项目已有工作流，才能使当前灰度覆盖产生实际可用的增量。

**Independent Test**: 逐路径重放现有通过样本，在同一帧上比较 gray 输出及其 dBZ 数值；核对 CLI 和同步/异步读取结果，保留每条不能解码的具体原因。

**Acceptance Scenarios**:

1. **Given** 已有通过验证且匹配当前输入的灰度规则，**When** 获取该帧的 dBZ，**Then** 每个有效值等于其 gray 值乘 5/16；来源规则缩放产生的超上限值仅在反算时按224计算，原 gray 不改，结果记录来源、产品、路径、规则、编码版本和截断位置/数量。
2. **Given** 路径处于 blocked、difference_pending，或规则证据不再匹配输入，**When** 请求 gray 规则生成 dBZ，**Then** 返回明确的不可用或输入不兼容结果，原图回退不会被当作 dBZ 成功。
3. **Given** RainViewer composite、TW grid 或 RDCAP reflectivity 已有直接数值解码，**When** 请求其 dBZ，**Then** 继续保留原有数值、质量和坐标语义，不额外经过 0～224 灰度量化；RDCAP 在线未验收的状态继续单独记录。
4. **Given** 多条路径中同时存在成功、无资料和解码不可用，**When** 批量读取，**Then** 保留每项状态和成功结果，CLI 与同步/异步 SDK 对同一输入的值、质量和错误一致。

---

### User Story 4 - 保存可追溯的 dBZ 成果并复用已有数据 (Priority: P2)

数据使用者希望保存和重新打开反射率成果，知道这些数值来自旧灰度约定，以及裁剪、饱和、修补、缩放和定位信息的限制；旧成果和原始缓存继续可用。

**Why this priority**: 让解码数据能被后续分析或雷达应用读取，并避免命名迁移破坏已有用户数据。

**Independent Test**: 对有定位和无定位的离线样本分别保存并独立读回，核对值、质量、单位、时间和坐标限制，再验证重复运行和历史资料读取。

**Acceptance Scenarios**:

1. **Given** dBZ 结果只有像素网格，**When** 保存数值成果，**Then** 可使用现有数值输出形式保存行列、值、质量和编码来源；地理定位保持未知，要求真实定位的地理输出或重网格被明确拒绝。
2. **Given** 结果有可信有效时刻、网格和对应处理关系，**When** 按已有适用格式保存并读回，**Then** 值、质量、单位、时刻、坐标和转换记录一致。
3. **Given** 已知某些像素被背景屏蔽、修补或插值，**When** 生成 dBZ 成果，**Then** 保留能由现有处理证明的质量信息；最终灰度图已经丢失的信息不被伪装成恢复成功。
4. **Given** 旧命名的规则、缓存或正式成果，**When** 安装新版本后读取或重跑，**Then** 旧数据可读取和核对；单纯改名不改变原始身份，实际新增灰度到 dBZ 处理具有可区分的成果身份，不错误跳过旧显示成果。

### Edge Cases

- 灰度 0 与 224 是有效编码端点；裁剪前的负值和超过上限的数值无法由最终图像恢复。
- 完全透明像素即使带非灰度或大于 224 的隐藏颜色，也仍是缺测；半透明像素保留已有透明度信息，不把 alpha 乘进灰度算术。16 位透明度按原值判断，仅 0 完全透明；1、255、256、65535 不因显示转换被当成缺测，可用原透明度在数值保存/读回中无损保留。
- 不透明黑色可能是有效编码零，也可能是旧转换写入的背景；有可追溯掩码时按掩码解释，仅剩图像且无法区分时记录该限制，不宣称识别了所有无雨/缺测。
- 同样的 0～224 值域可能来自普通亮度图；来源请求需已匹配规则，本地文件需明确编码声明，不能仅靠范围或文件名自动识别。
- 灰度已经被缩放、插值、修补、量化或裁剪；反算只恢复最终编码对应的值，不能还原原始未处理观测。
- 已验证来源 gray 的缩放可能产生225～255的整数灰度；按用户确认，仅反算时截断到224并记录调整。原gray像素及历史验证不变；本地裸文件不自动继承来源例外，已有缺测/站外/未知色仍为无效。
- 只有部分产品或站点有通过规则；不能把路径能力推广到整个 source，不能把 CA/NZ 等产品名称中的 rain 自动解释为雨强。
- GIF 多时次、多个 artifact、多站或多变量存在歧义时，沿用明确单帧选择规则；不能把显示图例、终端截图或已着色的 dBZ 预览作为输入编码。
- 无时刻、无坐标的本地文件与有完整来源记录的帧分别展示；不从文件读取时间生成有效时刻，也不从站心猜测图像范围。
- 模式冲突、错误单位、过期规则、超限、取消和输出中断均产生明确失败；不能留下可被复用为成功的半成品。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将 raw 定义为原始资料、gray 定义为约定灰度编码/灰度显示、dbz 定义为反射率数值处理；物理单位写作 dBZ。
- **FR-002**: 系统 MUST 接受用户已确认的旧灰度反射率编码关系：有效整数灰度 0～224 按 `gray / 16 * 5` 得到 0～70 dBZ；此版不重新要求独立上游标定才能进行这项编码反算。
- **FR-003**: 系统 MUST 为灰度编码生成可计算的反射率值、质量和行列网格，并支持 CLI 预览、同步/异步 SDK 读取及适用成果保存；缺少地理定位不阻止像素空间解码。
- **FR-004**: 系统 MUST 校验可见像素的灰度一致性、整数值和范围。本地声明输入的越界，以及所有输入的非灰度颜色、非整数、非有限值、损坏或不支持情形 MUST 明确拒绝。唯一来源例外是：由匹配的已有通过 gray 规则生成的超224整数值，MUST 仅在 dBZ 反算时截断到224，原gray不改；MUST 保留截断位置、数量、策略和对应身份，不能隐式调整或把已知无效像素转为有效。不得取亮度或截断小数来接受非法输入。
- **FR-005**: 系统 MUST 将 alpha=0 保留为缺测，按编码将没有已知无效掩码的不透明灰度 0 解为 0 dBZ；alpha 非零时不缩放数值，已有透明度或其限制保留在结果信息中。
- **FR-006**: 系统 MUST 保留已知背景/站外/未知色/修补/插值的区别及已有质量定义。灰度转换丢失的掩码或质量信息 MUST 标明不可恢复，不新增没有依据的像素级判定，也不能把已知无效像素写成有效零。
- **FR-007**: 系统 MUST 标明灰度解码得到的是量化/可能裁剪后的编码对应 dBZ，保留已知处理历史及FR-004来源例外的截断记录；不能宣称恢复了原始负值、超过上限的值、原始未缩放网格或未知扫描高度。
- **FR-008**: CLI MUST 提供 `--gray` 和 `--dbz` 作为本功能的规范模式名称，覆盖来源与适用本地文件预览；raw、gray、dbz 的不同模式选择 MUST 互斥，缺省原图预览与现有时间选择语义保持一致。
- **FR-009**: 本版 MUST 保留 `--legacy-display`、`--decoded` 及对应已有公开名称的兼容入口；旧入口解析为相应 gray/dbz 行为，合法历史调用结果不得因单纯改名改变。历史泛化科学调用或非 dBZ 文件 MUST 继续保留真实物理量，不能被兼容映射强行改单位。
- **FR-010**: 活动 CLI 帮助、报告、错误、README、用户文档、SDK 说明以及相关代码/资源/验证入口的语义命名 MUST 统一 gray/dbz；与灰度显示相关的 legacy 名称仅保留于明确标识的兼容入口和历史读取。通用旧格式兼容中的 legacy 和非反射率科学对象不按词面批量改名。
- **FR-011**: 当前输出 MUST 能区分 raw、gray、dbz，并保留现有报告中的来源、时间、状态和错误信息；新模式字段或取值的契约变化 MUST 明示，迁移提示不能破坏 JSON、管道和退出码。历史模式和字段须可被兼容读取。
- **FR-012**: 通过来源获取生成 dBZ 时，系统 MUST 按 source/product/path、必要的站点和输入约束匹配已有通过规则，再由其实际 gray 输出反算。blocked、difference_pending、未知路径或失效证据不能自动启用该路径；规则运行失败不能以原图回退冒充成功。
- **FR-013**: 本版 MUST 纳入当前灰度证据表全部 15 条 passed 路径的编码解码验收；每条都须给出该路径的 gray 像素一致性、dbz 算术及质量/处理限制结果。通过已有灰度生成和本版反算不要求将该来源的独立上游物理/地理验证同步标为通过。
- **FR-014**: 其余 8 条 blocked 路径 MUST 继续逐项保留原因；RainViewer 的旧 gray 路径和 TW grid 的旧显示记录处于 blocked，不得据此禁用它们已验证的直接数值解码。
- **FR-015**: 已有直接数值反射率产品 MUST 继续按自身已验证规则提供 dBZ，优先保留其数值和质量精度；不得为了统一命名而先量化为灰度再反算。其他物理量仍使用原有变量与单位，显式请求不适用的 dBZ 时给出单位/能力错误。
- **FR-016**: 对无可信来源关联的本地图像，系统 MUST 仅在用户显式选择约定灰度编码解码时应用公式，并记录输入摘要与该声明；仅打开文件、灰度外观或值域吻合不构成自动编码识别。已匹配来源灰度规则时保留其独立证据出处。
- **FR-017**: 系统 MUST 保留或准确表示图像尺寸、行方向和已知裁剪/缩放关系。有完整时刻/几何证据时，结果 MUST 正确承接对应信息；否则仅声明像素网格和未知项，不生成虚假经纬度、CRS 或有效时间。
- **FR-018**: 系统 MUST 支持像素空间 dBZ 结果的数值保存与独立读回；已有 NetCDF/Zarr 输出的适用结果可以使用行列坐标并明确缺少地理定位。有地理要求的 GeoTIFF、地理重网格等操作 MUST 在几何不足时拒绝；具有所需证据的 PNG/NetCDF/GeoTIFF/Zarr 继续满足各自格式契约。
- **FR-019**: dBZ 结果和正式成果 MUST 携带输入身份/摘要、来源或本地声明、gray 规则/编码版本、反算关系、质量/处理限制和已知时间/网格；原图、gray 图像与 dbz 数值的处理身份可区分，旧显示成果不能被错误复用为新的反射率成果。

  对直接原生或已保存数值文件，仅记录真实适用依据，不补造gray声明或反算历史。数值文件以实际内容和选择建立独立本地身份；文件中可用历史处理/来源记录保留为上游出处，缺失则标未知，不伪造原始资料取得证明。带已校验文件身份的读取结果可再次保存，当前保存身份与上游成果引用分别记录。
- **FR-020**: 单纯语义命名迁移 MUST 不改变原始帧身份、raw 字节或已验证 gray 像素。历史规则/资源引用、证据摘要、旧 manifest/cache 和处理版本须可核对读取；实际数值/处理语义发生变化时 MUST 产生可区分的版本和成果，不覆盖历史证据。
- **FR-021**: CLI 与同步/异步 SDK MUST 对同一输入给出一致的 dBZ 值、质量、时间/网格、处理身份和失败分类；批量中的部分失败 MUST 保留全部目标结果和已经成功的数据。
- **FR-022**: gray/dbz 全流程 MUST 遵守已有网络选择、帧选择、共享期限、字节/像素/临时资源限制和取消行为；参数与能力错误尽可能在获取前拒绝，失败或取消不能提交可被视为完整成功的成果。
- **FR-023**: 文档 MUST 给出原图→gray→dbz 的来源示例、明确声明编码的本地示例、有/无几何的保存示例以及旧名称迁移说明；同时说明 5/16 dBZ 量化步长、0/224 端点、透明/背景区别、处理限制和来源级验证范围。
- **FR-024**: 验收记录 MUST 分开描述灰度匹配、编码对应 dBZ 解码、原始物理数值/几何验证和在线获取能力；本版完成不能自动关闭旧 specs 的缺材料、云存储、来源 live 或发布验收项。

### Key Entities *(include if feature involves data)*

- **Gray 编码资料**：整数灰度像素、透明度、图像尺寸、来源/本地声明、编码/规则版本和输入摘要；可关联已知无效掩码与处理历史。
- **dBZ 数据结果**：编码对应的反射率数值、dBZ 单位、质量、行列网格、可选时刻/地理定位及处理限制；区别于显示图像和原始资料。
- **路径解码能力**：source/product/path、适用站点/输入约束、gray 验证状态、dbz 编码反算状态、独立物理/地理与在线能力；这些状态分别记录。
- **名称迁移映射**：规范 gray/dbz 名称、旧入口及其适用语义、历史资源/字段读取关系；用于保证当前操作和历史数据可追溯。
- **成果记录**：资料与处理身份、值/质量/坐标文件、完整性信息及可复核的转换来源，供保存、读回和幂等复用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对 0～224 全部 225 个有效整数灰度，读取出的 dBZ 均等于 `gray * 5/16`，最大绝对误差不超过 0.000001 dBZ；0、16、32、160、224 的结果分别为 0、5、10、50、70。
- **SC-002**: 透明、有效黑色、已知背景、未知颜色、非整数、越界及损坏输入的代表场景 100% 符合质量/失败规则；不存在把非法输入、已知无效像素或 raw 回退报告为成功 dBZ 的情况。
- **SC-003**: 当前全部 15 条 passed 灰度路径均有来源到 gray 再到 dbz 的离线核对：gray 与既有基准逐像素一致；dbz 有效像素按 `min(gray,224) * 5/16` 满足SC-001误差门槛；超上限像素的截断位置/数量可核对，已有无效掩码不被清除。各路径明确其质量和几何限制；其余8条blocked路径无自动启用。
- **SC-004**: 同一组离线资料经 CLI、同步和异步读取，数值、质量、模式、单位、身份与错误分类全部一致；现有三类直接数值反射率产品的基准数值/质量/坐标不因本次灰度处理或改名变化。
- **SC-005**: 新帮助、活动示例和报告均能明确区分 raw/gray/dbz；灰度展示功能在活动命名中无未说明的 legacy 名称，反射率操作无未说明的旧科学解码称谓；所有保留旧入口均有迁移映射和等价离线案例。
- **SC-006**: 有定位与无定位的代表 dBZ 成果均能在适用数值格式中独立读回，值误差不超过 0.000001 dBZ，质量与已知时间/网格一致；无定位结果不含推测的地理信息，全部不适用地理操作明确拒绝。
- **SC-007**: 重复运行、历史资料读取、模式冲突、资源超限、部分失败和取消的代表验收全部满足既有完整性/状态规则；原始资料不改写，纯改名不改变其身份，新增 dbz 处理不误判为旧 gray 成果。
- **SC-008**: 每条已启用路径都可从结果或成果记录查到编码、规则/输入依据和已知限制；文档同时提供来源/本地解码、gray/dbz 区分及旧名称迁移的完整可执行流程，读者无需了解历史项目内部实现即可判断数值来源与是否有地理定位。

## Assumptions

- 用户已确认旧项目灰度编码与 dBZ 的算术对齐，本版将它作为明确支持的编码约定。范围一致是输入校验的一部分；来源关联或用户明确声明提供采用该约定的依据。
- 首版目标是最终 gray 像素对应的 dBZ；量化、裁剪、背景处理、修补或缩放前的信息可能已丢失，不以本版公式推定其可逆或重新标定全部上游产品。
- 未另行指定兼容策略时，新名称成为默认文档/帮助口径，本版保留旧公开名称作为兼容入口；内部业务命名使用 gray/dbz，历史引用有明确标识。非反射率量和通用数据容器继续保留准确语义。
- 纳入的通过路径快照为：`au/composite`、`ca/rain`、`es/composite`、`fr/composite`、`id/composite`、`kr/composite`、`my/composite/east`、`my/composite/peninsular`、`nz/rain`、`pt/composite`、`sg/composite`、`th/composite/kkn240Loop`、`th_royalrain/cappi`、`tw/observation`、`vn/cmax`。状态依据为 [当前灰度验证记录](../../validation-results/legacy-display.json)；实施时以匹配当前输入且证据有效的逐路径规则为启用条件。
- 本版复用 001 的数据/质量/成果契约、002 的灰度规则/证据与预览行为、003 的共用原生工作流及现有 004 反射率边界；依赖已有能力，不要求这些 specs 全部验收先闭合。依据：[001 data model](../001-radiust-v1-migration/data-model.md)、[002 灰度显示契约](../002-cli-experience/contracts/legacy-display.md)、[003 SDK 契约](../003-rust-core-performance/contracts/core-sdk.md)、[004 科学与持久化契约](../004-rdcap-single-station/contracts/science-persistence.md)。
- Scope in：约定 gray→dbz 首版、15 条已有通过路径的集成、明确声明的本地灰度文件、像素/适用地理成果、相关 CLI/docs/代码活动命名与旧入口/历史数据兼容。
- Scope out：补齐 blocked 来源样本或替换其算法、新数据源、雨强推导/降水累积、反演原始未量化观测、新地理标定/投影能力、桌面界面、真实云存储及新平台验收。旧 specs 和历史验证文件作为原始依据保留；活动名称迁移通过兼容映射承接历史引用。
- [项目 constitution](../../.specify/memory/constitution.md)目前仍是未填写模板，不将其中示例原则当作已批准治理约束。本规格只定义本次功能与命名边界。
